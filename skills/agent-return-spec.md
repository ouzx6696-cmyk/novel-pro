# Agent Return Specification

本文件定义 agent 的返回描述规范。不强制所有 agent 使用统一格式（不同角色的返回产物结构不同），但每个 agent 文件中的"返回"描述必须覆盖以下四要素，确保 novel-agent 在收到返回后能做出一致的路由判断。

## 四要素

1. **写入产物**：本 agent 实际写入了哪些文件或报告。格式：文件路径或"不写产物，仅返回报告"。

2. **返回摘要**：novel-agent 判断完成与否所需的关键信息。对于规划角色：文件路径 + 关键事实摘要。对于 writer：正文是否完整。对于 reader/reviewer：verdict + 建议处理角色。

3. **下一跳信号**：如果返回结果决定了下一 operation 的选择，明确写出判断依据。例如 Reader 返回的"建议处理角色"字段决定了 `full.repair` 中的分流路由（writer / prompt-crafter / planner / anti-ai）。

4. **失败/冲突证据**：无法完成时的具体缺口描述（缺失的前提事实、规划冲突的位置、Prompt 无法执行的根因、需要上游处理的问题）。

## agent 文件修改原则

- 已有 agent 文件的返回描述如果已覆盖四要素，不强制改写措辞。
- 新建 agent 文件时必须遵循本规范，在 `## 返回` 或等效节中覆盖四要素。
- 此规范不改变已有 agent 的行为，仅作为一致性参照。novel-agent 在阅读 agent 返回时，可以从任意格式的返回中提取四要素。
