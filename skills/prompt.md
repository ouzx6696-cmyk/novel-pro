# Prompt Creation

Prompt 把章纲中的故事任务转成 writer 可以直接展开的单章行动过程。每章拥有一个独立 Prompt；创建任务以一幕为单位，长幕以连续叙事批次为单位。

## 作者确认前置条件

创建任务开始时，先读 `story.md` 的目标卷行。`author_confirmed` 是本卷卷纲、必要设定和项目文风已经由作者确认的唯一持久事实；不新增或推导第二套 style 状态。目标卷的 `author_confirmed` 缺失或为 `false` 时，prompt-crafter 只返回需要作者确认的范围和缺口，不写任何 `prompts/` 文件，也不推进 `prompts.ready`。

## 任务范围

普通长度的幕由一个 prompt-crafter 顺序创建该幕全部 Prompt。它先理解整幕如何从 `start_state` 走向 `end_state`，再逐章形成独立文件。

长幕按人物目标、关系、信息、资源状态、重大转折和唯一事件的稳定交接划分连续批次。一个 prompt-crafter 处理一个批次中的多章，批次之间按幕内顺序推进。批次可以帮助安排调度，但不决定批次边界。

任务范围与产物粒度相互独立：

```text
创建任务：一幕或一个连续批次
最终产物：一章一个 prompts/vol-N-ch-M.md
```

## 创作上下文

prompt-crafter 的知识输入默认来自本卷 `settings/context-pack.md`（预制包）：它由本卷首个 `prompt.create` 任务按 `skills/context-pack.md` 从知识库裁剪压缩而成，覆盖题材、连载基线、剧情/场景/人物方法。后续任务读这一包即可，不再逐章下钻 `knowledge/`。本卷首个 `prompt.create` 任务尚未形成 pack 时，先按 `skills/context-pack.md` 建包，再继续创建章级 Prompt。

prompt-crafter 从当前幕纲、任务范围内的章纲、批次入口和出口、必要人物设定、已确认项目文风、题材、作者确认偏好、伏笔、时间线、有效正文入口和少量相关知识建立幕内理解。它只读取与当前章有关的项目事实，不把原始设定整段搬进 Prompt。

Prompt 的自包含性标准见 `knowledge/scene/self-contained-prompt.md`（三自原则、各字段嵌入规则、幕级上下文转化方法、自检协议）。prompt-crafter 在创建每份 Prompt 后必须执行自检协议中的五项检查；Prompt 中不允许出现章/幕/卷编号引用、外部文件引用或未嵌入的叙事意图。

`settings/writing-style.md` 提供本项目的声线锚点（基准样章、对照示范、节奏配比和声线禁区），`settings/genre-setting.md` 提供题材期待。创建者从文风文件中提取当前章节场景最需要的声线特征、节奏型和禁用表达，转化为 Prompt"本章质感"小节的结构化正向写作材料，并选取一句样句作为即时锚点，使 writer 不必再回到这些来源寻找上下文。

Prompt 只锁定会影响后续承接的事实、人物选择和场景压力，不替 writer 写完对白或安排每个动作。把知识改写成当前人物能感知、能误判、能采取的行动；不要把“紧张、感人、爽、真实”当作可执行指令。

如果文风文件仍是占位符、只有抽象形容词，或没有作者确认的样章，先把缺口和需要作者选择的方向返回顶层，不要自行补成通用模型腔。Prompt 可以暂缓，不能用“本章质感”四个空泛词掩盖声线尚未形成。

文风原型库只参与项目文风形成，不参与每章 Prompt 的默认读取。项目文风确认后，prompt-crafter 只提取当前章节需要的声线特征、一个原创化样句方向和少量边界；不要把原型名称、来源印记或整套原型规则写进 Prompt。

## 单章 Prompt

每份 Prompt 独立写入 `prompts/vol-N-ch-M.md`：

```markdown
---
prompt_contract: 2
chapter: vol-1-ch-1
act: vol-1-act-1
target_chars: 4000
min_chars: 3200
---

## 本章要完成的变化
- 幕内作用：{本章在当前幕中的作用}
- 核心变化：{人物、关系、信息或局势的不可撤回变化}
- 读者期待：{本章回应、加深或转移的问题}
- POV：{人物与限知边界}

## 承接现场
- 时间与地点：{具体入口}
- 上一章留下的动作或状态：{本章从哪里开始}
- 当前压力：{人物为什么必须行动}

## 人物发动机
- {人物}：表层目标；不愿承认的需求或恐惧；已知、未知或误判；可用筹码；不能退让的理由；在关系中想保住什么；可能采取的自我保护动作

## 场景推进

### 场景：{名称}｜权重：核心/承接/转折
- 入场状态：{人物、地点和正在发生的动作}
- 目标与阻力：{人物想取得什么；谁或什么阻止他}
- 行动与反制：{双方怎样试探、施压、交换、追逐或调整}
- 转折与选择：{什么改变判断；人物作出什么有代价的选择}
- 可见结果：{关系、信息、资源、风险或局势怎样变化}
- 下一步触发：{结果怎样逼出下一场或下一章}
- 展开重点：{最值得写足的博弈、情绪或身体经验}
- POV 现场：{人物此刻真正看见、听见、触到或误判的东西；空间、时间或物件怎样限制行动}
- 潜台词与余波：{表面说什么、实际想推动或遮掩什么；场景结束后谁因此改变了什么}

## 必守事实与边界
- 必须发生：{通过人物行动交付的变化}
- 相关事实：{当前章真正需要的身份、能力、资源和信息阶段}
- 保留边界：{会影响后续承接的事实范围}

## 收束画面
{具体动作、证据、选择或新状态}

## 本章质感
- 声线要点：{从 writing-style.md 基准样章中提取本章最需体现的少量声线特征}
- 本章节奏：{本章的段落节奏型、对白/叙述配比倾向、感官密度}
- 禁用表达：{本章特别需要规避的声线禁区项，从 writing-style.md 禁区中选取与本章场景相关的}
- 样句示范：{从基准样章或对照示范中选取一句最贴合本章氛围的句子，作为 writer 的即时声线锚点}
- 人物声音与留白：{哪些话应说得直、哪些只通过动作或停顿留下；不要把情绪解释完}
```

Prompt 通过人物行动组织内容。事件名称、结果清单、方法标签和抽象主题不能代替人物目标、阻力、反制、选择与后果。写作者不必按字段顺序写正文，也不必逐项显式交付；字段只是保证关键因果不丢，正文仍应像人物在当下做事、说话、犹豫和承担后果。

`target_chars` 和 `min_chars` 只是分配场景展开空间的粗略参考，不是交付下限、质量评分或注水理由。篇幅应服从人物选择、读者理解和场景余波；关键处需要更多空间时可以超出，过渡处成立时也可以更短。

## 幕内连续性

prompt-crafter 按章节顺序创建文件。每章的收束与下一章入口共同来自幕纲和章纲；批次结束时确认出口能够交给下一批次继续创建。

创建者遇到幕纲和章纲无法共同成立的情况时，把冲突和受影响范围返回顶层。Prompt 不替规划层改写上位事实。

## 完成语义

当前幕或 batch 完成后，顶层继续长期目标范围内的下一段 Prompt 创建。长期 `range` 内每章的 Prompt 全部创建并落盘后，cursor 才进入 `prompts.ready`；这个节点表示所选写作范围已经可以整体进入 Fast 或 Full。

## 显式 Prompt 审查

只有用户明确提出审核提示词时，顶层创建 prompt-reviewer，并建立临时 `prompt.review` 任务。

reviewer 先单独阅读目标 Prompt，判断它自身能否形成清楚、可执行的人物行动；随后只增加所在幕纲和对应章纲，核对 Prompt 与规划的关系。审查结果写入当前 task，不改变默认 Prompt 创建链。
