# Prompt Creation

Prompt 把章纲中的故事任务转成 writer 可以直接展开的单章生成包：先嵌入上一章真实正文提取的「前情上下文」与角色档案回流的状态，再用连贯叙述写清本章故事与承接、人物动机与情绪的递进，把场景技法与声线逐场溶解进场景展开。每章拥有一个独立 Prompt；**创建任务以单章为单位，跟随正文顺序逐章创建**——第 M 章 Prompt 创建时，第 M-1 章必须已经验收（写作模式）或提交（编辑模式），前情直接取自真实正文。

## 作者确认前置条件

创建任务开始时，先读 `story.md` 的目标卷行。`author_confirmed` 是本卷卷纲、必要设定和项目文风已经由作者确认的唯一持久事实；不新增或推导第二套 style 状态。目标卷的 `author_confirmed` 缺失或为 `false` 时，prompt-crafter 只返回需要作者确认的范围和缺口，不写任何 `prompts/` 文件。

## 任务范围

一个 prompt-crafter 处理**一章**，形成 `prompts/vol-N-ch-M.md`。顺序链路（见 `skills/writing.md`）保证：创建第 M 章 Prompt 时，第 M-1 章已验收/提交，其真实正文与已回流的状态文件（角色 `state_history`、`timeline.md`、`foreshadowing.md`）都在场。首章（卷首或每幕首章）的前情来自幕纲 `start_state` 与上一幕最后一章的真实正文（若已存在）。

## 创作上下文

prompt-crafter 的知识输入默认来自本卷 `settings/context-pack.md`（预制包）：它由本卷首个 `prompt.create` 任务按 `skills/context-pack.md` 从知识库裁剪压缩而成，覆盖题材、连载基线、剧情/场景/人物方法。后续任务读这一包即可，不再逐章下钻 `knowledge/`。本卷首个 `prompt.create` 任务尚未形成 pack 时，先按 `skills/context-pack.md` 建包，再继续创建本章 Prompt。

幕级理解优先来自 `chapters/vol-N-act-K-handoff.md`（幕级承接快照，由 chapter-planner 在完成本幕章纲后生成）：它汇总承接入口、本幕变更事实链、must_hold 与幕间接口，替代逐文件重建幕级理解。快照缺失或与幕纲/章纲不一致时，才从当前幕纲、章纲、上一章真实正文入口、必要人物设定、已确认项目文风、题材、作者确认偏好、伏笔、时间线、有效正文入口和少量相关知识建立幕内理解。它只读取与当前章有关的项目事实，不把原始设定整段搬进 Prompt。

**上一章真实正文入口（必读）**：创建第 M 章 Prompt 前，必须完整阅读上一章验收稿（`drafts/vol-N-ch-M-1.md`）或已提交正文（`texts/vol-N-ch-M-1.md`），按幕内/跨幕区分读取方式：

- **同幕内（第 M 章与第 M-1 章同属一幕）**：读上一章**全文**——不仅提取前情三件套，还要从全文建立本章承接的质感（情绪节奏、对白习惯、段落呼吸），让「本章故事」的叙述示范与上一章真正接得上；上一章信息密度高、跨章因果延续时，可再补读前二章（按需，不无限扩大；更早章节靠状态文件与幕总结）。
- **跨幕（第 M 章是本幕首章）**：读**幕末正文总结** `summaries/vol-N-act-K-1.md`（上一幕，必读）——幕内事件链、人物状态、信息差、伏笔、未闭合张力与幕末承接帧，作跨幕导航；同时仍读上一章**结尾画面**（幕末承接帧在幕总结中已含，但以前一章真实正文末尾为准核对）。

两种方式都要提取「前情三件套」写入 Prompt 的「前情上下文」块：

1. **上章结尾画面**：从上一章末尾提取 30-50 字的具象画面（人物在做什么、留下什么可见证据）。**选取规则**：取"人物动作 + 可见证据 + 未闭合张力"三者俱全的最后一组句子——不是逐字复制，而是压缩改写为连贯叙述句；若上一章末尾是纯环境、抒情或总结收束，向回找最后一个"人物动作+证据"的节点，不把环境余白当画面；画面必须能让 writer 直接接着写，不需要回读原文。
2. **读者情绪残留**：一个情绪词（不是分析），来自上一章情绪落点。**选取规则**：必须是情绪词本身（压抑、紧绷、松一口气、寒），不是评价词（"写得克制"），也不是情绪分析句（"他感到压力很大"）；写不出一个词，说明上一章收束的情绪落点不成立，回告顶层。
3. **上章留下的缺口**：读者期待但还没发生的事，1 句（以章纲 `reader_effect`/`ends_with` 与正文实际收束核对）。**选取规则**：必须是读者能指认的具体未解事项（"张氏开出的条件是什么""他会不会答应"），不是方向性抽象（"更大的阴谋在酝酿"）；正文实际收束与章纲承诺不一致时以正文为准，并在自检表注明。

**角色当前状态（必读）**：读取出场角色档案的 `state_history` 节（倒读最近状态块重建知识存量与当前位置）、`timeline.md` 最近条目与 `foreshadowing.md` 台账，写入 Prompt 的「角色初始状态」块。**选取规则**：只写本章出场且状态会影响行动的人物；每人 2-3 句状态快照（位置/身体状态/已知信息/持有物/微习惯锚点）；已知信息必须与 `state_history` 最新一条一致；状态文件与上一章正文不一致时，以正文为准并回告顶层（对应章节状态同步可能未完成）。

Prompt 的自包含性标准见 `knowledge/scene/self-contained-prompt.md`（三自原则、各节嵌入规则、幕级上下文转化方法、自检协议）。prompt-crafter 在创建每份 Prompt 后必须执行自检协议中的九项检查；Prompt 中不允许出现章/幕/卷编号引用、外部文件引用或未嵌入的叙事意图。frontmatter 的 `preceding_source` 只作审计追溯，不进入正文引用。

`settings/writing-style.md` 是本项目的**风格提示词**（两部分：**第一部分「本书写作基调与创作逻辑」**——叙事者/语言气质/情绪处理/信息差管理/节奏/群像/事实纪律/文章结构，是逐章生效的创作决策依据；**第二部分「写作技巧」**——基准样章/对照示范/逐项指示句/声线禁区，是逐场溶解的执行技法；描述均为可执行指示句），`settings/genre-setting.md` 提供题材期待。创建者按两部分分别提取：**第一部分 → 全章基调与创作逻辑**——用它亲自书写"本章故事"的叙述（视角、情绪外化、信息差暴露、节奏换气、结构组织），让故事叙述本身成为 writer 拿到的第一声线示范；其中 1.2 创作逻辑（硬时钟、群像纪律、信息差边界）落入「必守事实与边界」。**第二部分 → 逐场声线落点**——为每场按指示句选取句长倾向、对白与叙述配比、感官密度、留白位置和一句样句锚点，写入该场的"本场声线"，禁区条目核入本章边界。writer 不必再回到这些来源寻找上下文。

**低自由度**：风格提示词已写成明确指示句，提取与书写按指示执行，不自由发挥、不替换成抽象形容词；抽象词的判断留给作者的，是声线漂移与质量波动的来源。跨章稳定由同一份风格提示词保证——不因幕、章节顺序或创建者不同而改变声线依据。

Prompt 用连贯叙述锁定会影响后续承接的事实、人物选择、场景压力和代价，不替 writer 写完对白或安排每个动作。"本章故事"和各场叙述写清发生什么、为什么发生、谁付出什么代价；对白措辞、动作编排、段落切分仍是 writer 的现场创作。把知识改写成当前人物能感知、能误判、能采取的行动；不要把"紧张、感人、爽、真实"当作可执行指令。

如果文风文件仍是占位符、只有抽象形容词，或没有作者确认的样章，先把缺口和需要作者选择的方向返回顶层，不要自行补成通用模型腔。Prompt 可以暂缓，不能用空泛的声线形容词掩盖声线尚未形成。

文风原型库只参与项目文风形成，不参与每章 Prompt 的默认读取。项目文风确认后，prompt-crafter 只提取当前章节需要的声线特征、各场样句方向和少量边界；不要把原型名称、来源印记或整套原型规则写进 Prompt。

## 建包返回摘要

本卷首个 `prompt.create` 任务在建包后、创建本章 Prompt 前，向顶层返回一份建包摘要，供顶层低成本抽查包质量：

- 题材执行要点一句话（本卷题材期待如何被压缩进包）。
- 已确认边界清单（题材边界、作者边界、声线禁区是否入包）。
- 来源清单（实际读取的索引与子文件，与 `settings/context-pack.md` 头部 `sources` 一致）。
- 一致性声明（包内容与 `settings/genre-setting.md`、`settings/writing-style.md` 已确认内容是否对齐，冲突时注明）。

顶层据摘要抽读 pack 一节核对；发现压缩失真或遗漏时按 `skills/context-pack.md` 的补包/重建规则处理。

## 单章 Prompt

每份 Prompt 独立写入 `prompts/vol-N-ch-M.md`，由六块组成：前情上下文、本章故事、角色初始状态、人物动机与情绪、场景展开、必守事实与边界。叙述型主体（本章故事、人物动机与情绪、场景展开）以连贯叙述承载声线与技法，不设独立的声线分节。

```markdown
---
prompt_contract: 4
chapter: vol-N-ch-M
act: vol-N-act-K
preceding_source: {上一章验收稿/定稿路径；首章为"幕纲 start_state"}
target_chars: 4000
min_chars: 3200
---

## 前情上下文
上章结尾画面：{从上一章真实正文末尾提取的 30-50 字具象画面：人物在做什么、留下什么可见证据}
读者情绪残留：{一个情绪词，不是分析}
上章留下的缺口：{读者期待但还没发生的事，1 句}

## 本章故事
{300–500 字连贯叙述。从「前情上下文」的收束画面起笔：人物此刻在什么时间、什么地点、手上有什么、刚发生过什么、眼下被什么逼着；然后讲清本章要走的完整一段路：遇到什么阻力、经过几次交锋、在哪里转向、付出什么代价；最后落到收束的新状态。这段叙述本身用项目声线来写，它就是 writer 拿到的第一声线示范，胜过任何形容词。}

收束：{正文停在哪个具体画面：人物在做什么、留下了什么可见证据，1 句}
读者期待：{本章回应、加深或转移的具体问题，1–2 句}

## 角色初始状态
{每个出场人物 2–3 句状态快照（本章开场时）：位置、身体状态、已知信息、手上持有物、微习惯/小动作锚点。从角色档案 state_history 倒读 + 上一章真实正文结尾提取；只写本章会实际作用的条目。}

## 人物动机与情绪
{每个出场人物一小段连贯叙述（3–5 句）：他进场时想要什么、怕什么、误判了什么（起点）；本章哪个事实或压力会撬动他（施压点）；他的目标或情绪在哪一刻转向、转向后剩下什么（落点）。写递进弧线，不写此刻快照；不写性格标签。}

情绪线：{全章情绪从什么基调起、在哪一场升或压、收在什么温度；对应该章节奏型：哪里密集推进、哪里放缓换气，1–2 句}

## 场景展开

### 场景：{名称}｜权重：核心/承接/转折
{3–6 句连贯叙述讲这场戏怎么过：谁带着什么进场、想要什么、被什么挡住、双方怎样试探施压、什么改变了判断、人物付出什么代价、留下什么新局面。}
- 行动脉络：入场状态 → 目标与阻力 → 行动与反制 → 转折与选择 → 可见结果 → 下一步触发（各环节一句完整话，锁定因果，不编排对白措辞）
- 本场怎么写：{针对这场戏的性质（对峙/试探/日常/追逐/独处……）给出的 2–4 条具体展开指导，从 context-pack 技法转化为本场的动作、对白、感官设计；落到这一场的人、事、物上，不点名方法名，不写放之四海皆准的抽象指令，多场之间不得复诵同句}
- 本场声线：{这一场的句长倾向、对白与叙述配比、感官密度、何处留白（哪些话直说、哪些只给动作和停顿），加一句样句锚点（从 writing-style.md 基准样章选取或按其声线原创）}

## 必守事实与边界
- 信息差变化：开场 {谁知道什么 ↦ 谁不知道什么} → 结尾 {本章后留下的新信息差，驱动下一章}
- 必须发生：{通过人物行动交付的变化}
- 相关事实：{本章真正需要的身份、能力、资源、信息阶段}
- 保留边界：{会影响后续承接、本章不能动的事实清单}
```

Prompt 通过人物行动组织内容。事件名称、结果清单、方法标签和抽象主题不能代替人物目标、阻力、反制、选择与后果。写作者不必按小节顺序写正文，也不必逐节显式交付；叙述与骨架只是保证关键因果不丢，正文仍应像人物在当下做事、说话、犹豫和承担后果。

`target_chars` 和 `min_chars` 只是分配场景展开空间的粗略参考，不是交付下限、质量评分或注水理由。篇幅应服从人物选择、读者理解和场景余波；关键处需要更多空间时可以超出，过渡处成立时也可以更短。

## 四步转化法（章纲 + 上文 → 单章 Prompt 的过程）

写每份 Prompt 前，按四步把章纲与真实上文转化为人物可以经历的行动过程。四步是**写的过程**，与下方的自检（**写完的检查**）衔接，不是两套检查清单：

1. **锚定角色**：从章纲 `conflict` 与 `characters`、角色档案 `state_history`（倒读）出发，确立每个人物本章开场的状态快照与动机起点：表层想要什么、不愿承认什么、已知/未知/误判什么、筹码和底线在哪；只写本场会实际作用的条目，不写性格标签。起点快照写入「角色初始状态」块。
2. **角色认知重建（锚定信息差）**：从角色档案 `state_history` 的「信息持有」三条与上一章真实正文结尾，倒推每个角色"截至本章前"的知识存量（知道什么、不知道什么、坚持什么误判）；结合章纲 `info_gap` 明确本章的信息差关系与变化（开场 → 结尾新信息差）。信息差决定哪个事实或压力会在本章撬动人物，成为动机与情绪的施压点。`info_gap` 缺失或过简时，从幕纲 `start_state`/`end_state` 与 `scenes` 的对抗结构反推本场信息状态，不因字段可选而跳过这一步。
3. **锚定情绪递进**：从幕纲 `emotional_curve`、上一章情绪残留与章纲出发，确定每个人物在本章的转向与落点（目标或情绪在哪一刻变、变成什么），以及全章情绪线（从什么基调起、在哪一场升或压、收在什么温度）；情绪来自事件后果与人物反应，不来自抽象标签。
4. **溶解输出**：先写「前情上下文」三件套（上一章真实正文提取），再写「角色初始状态」快照，然后把承接、压力、交锋与代价写成连贯的「本章故事」叙述，叙述语言本身调用项目声线；再逐场写出场景叙述与行动脉络，按该场性质把场景技法溶解为「本场怎么写」的具体指导，把声线落为「本场声线」；最后把 `info_gap` 的变化落为「信息差变化」一行，关键选择留下余波。场景性质（对峙/试探/日常/追逐/独处等）以章纲 `scenes` 主导任务为判断依据，拿不准时按 `skills/planning.md` 的场景知识指引回读 `knowledge/scene/index.md` 对应条目，不凭感觉贴标签。

场景权重标注：每章标注 **1 个核心场景**（展开最充分，承担本章主要变化）与**至多 1 个低权重转场**（过渡性，控制篇幅）。低权重转场建议不超过 100 字：1 句环境 + 1 句动作 + 1 句氛围即可，不为凑字数展开；其「本场怎么写」与「本场声线」可从简合并为一两句。

## 案例骨架（六块结构示范）

下面是单章 Prompt 的六块结构骨架，示范每块应有的信息粒度与职责（示意结构，非固定文案）：

```markdown
---
prompt_contract: 4
chapter: vol-N-ch-M
act: vol-N-act-K
preceding_source: drafts/vol-N-ch-M-1.md
target_chars: 4000
min_chars: 3200
---

## 前情上下文
上章结尾画面：{上一章真实正文末尾 30-50 字} / 情绪残留：{一词} / 上章缺口：{一句}

## 本章故事
一段连贯叙述（300-500 字）：从上一章收束画面起笔，写入本章事件与人物动作，落在一个可见结果上；叙述语言本身即项目声线示范。后附一行收束画面、一行读者期待回应。

## 角色初始状态
每人 2-3 句：位置/身体状态/已知信息/持有物/微习惯锚点。

## 人物动机与情绪
每人一段：起点（表层想要什么、不愿承认什么、已知/未知/误判）→ 施压点（哪个事实或压力在章内撬动他）→ 落点（目标或情绪在哪一刻变、变成什么）。后附一行全章情绪线。

## 场景展开
每场四件齐，并标注权重（核心/转折/低权重转场）：
- 场景叙述：2-4 句，写事件与动作。
- 行动脉络：入场→目标阻力→行动反制→转折选择→可见结果→下一步触发。
- 本场怎么写：把技法溶解为具体指导，不复诵方法名。
- 本场声线：落到节奏、对白密度与留白处，附一句样句。

## 必守事实与边界
- 信息差变化：开场 {A知道↦B不知} → 结尾 {新信息差}
- 必须发生：本章不可绕开的事实。
- 相关事实：需要照应但不正面展开的背景。
- 保留边界：本章不揭破、不登场、不展开的内容。
```

## 自检结论

prompt-crafter 返回顶层时，必须按章附一行式自检表：覆盖 `knowledge/scene/self-contained-prompt.md` 自检协议九项检查（按返回粒度合并为七核对点）+ 字段完整性核对点。每项只填「成立」或「缺口 + 证据」，不评分、不写分析：

九项 → 核对点的合并映射：引用扫描 → must_hold 全部落入（不自包含、不引用外部文件）；前情上下文落地检查 + 承接闭环验证 → 前情取自真实正文且承接闭合；角色初始状态检查 + 叙述连贯与递进（人物部分）→ 角色初始状态完整且动机情绪有递进；可执行性检验（场景部分）→ 场景有行动-反制-选择-余波；信息差检验 → 信息差变化明确；技法溶解检验 → 每场声线有落点且不复诵；新人测试与状态具体性检验由顶层逐章阅读与字段完整性核对点共同承担。

```text
章节 | must_hold 全部落入 | 前情取自真实正文且承接闭合 | 角色初始状态完整且动机情绪有递进 | 场景有行动-反制-选择-余波 | 每场声线有落点且不复诵 | 信息差变化明确 | 字段完整性
vol-N-ch-M | 成立 | 成立 | 成立 | 成立 | 成立 | 成立 | 成立
vol-N-ch-Q | 缺口: 章纲 must_hold 的 X 事实未写入必守事实 | 缺口: 前情画面与上一章实际结尾不符 | ... | ... | ... | ... | 缺口: 角色初始状态缺持有物
```

字段完整性核对点：前情上下文三件齐（结尾画面/情绪残留/缺口）；本章故事含叙述 + 收束 + 读者期待；角色初始状态每个出场人物含位置/状态/已知/持有物/微习惯；人物动机与情绪每人含起点/施压点/落点且含情绪线；场景展开每场含场景叙述/行动脉络/本场怎么写/本场声线（缺低权重转场可注明从简）；必守事实与边界含信息差变化 + 三件齐。

自检表是顶层逐一读 Prompt 时的核对锚点：顶层对每份 Prompt 逐一读过（存在 ≠ 通过），逐行核对自检表；发现缺口时由 prompt-crafter 修复对应 Prompt，或按缺口性质返回规划层。自检结论的成立与否由顶层阅读验证，不构成脚本门禁。

## 顺序链路与承接

顺序链路下每章 Prompt 独立创建：第 M 章 Prompt 的前情上下文与角色初始状态直接取自第 M-1 章真实正文与已回流的状态文件，不再依赖批次出口摘要。创建者发现章纲/幕纲与已验收正文冲突时（如正文实际发展偏离章纲 `chapter_end_state` 或 `info_gap`），把冲突和受影响范围返回顶层，由顶层决定修正章纲后重试或由规划层调整；Prompt 不替规划层改写上位事实。

## 完成语义

本章 Prompt 创建完成：落盘 `prompts/vol-N-ch-M.md`、自检表无缺口、顶层阅读通过。随后进入本章的默认审计（`prompt.review`）与写作/编辑链路，见 `skills/writing.md`。不存在"全部 Prompt 就绪"的批量节点——Prompt 跟随正文顺序逐章创建，一章验收/提交后才创建下一章。

## 默认 Prompt 审计

`prompt.review` 是顺序链路的**默认步骤**（不再是用户显式请求的旁路）：每章 Prompt 创建并落盘后，顶层创建 prompt-reviewer 对该章 Prompt 做独立审计（9 维度，判定规则见 `agents/prompt-reviewer.md`）；审计不通过时返回 prompt-crafter 修复后重新审计，通过后才进入写作/编辑链路。

顶层也可按作者要求对单章跳过审计（作者明确放行时），并在 order 中记录。审计报告写入当前 task，不改变 Prompt 创建本身的所有权。
