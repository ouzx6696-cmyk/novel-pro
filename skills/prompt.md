# Prompt Creation

Prompt 把章纲中的故事任务转成 writer 可以直接展开的单章生成包：用连贯叙述写清本章故事与承接、人物动机与情绪的递进，再把场景技法与声线逐场溶解进场景展开。每章拥有一个独立 Prompt；创建任务以一幕为单位，长幕以连续叙事批次为单位。

## 作者确认前置条件

创建任务开始时，先读 `story.md` 的目标卷行。`author_confirmed` 是本卷卷纲、必要设定和项目文风已经由作者确认的唯一持久事实；不新增或推导第二套 style 状态。目标卷的 `author_confirmed` 缺失或为 `false` 时，prompt-crafter 只返回需要作者确认的范围和缺口，不写任何 `prompts/` 文件，也不推进 `prompts.ready`。

## 任务范围

普通长度的幕由一个 prompt-crafter 顺序创建该幕全部 Prompt。它先理解整幕如何从 `start_state` 走向 `end_state`，再逐章形成独立文件。

长幕按人物目标、关系、信息、资源状态、重大转折和唯一事件的稳定交接划分连续批次。一个 prompt-crafter 处理一个批次中的多章，批次之间按幕内顺序推进。批次可以帮助安排调度，但不决定批次边界。

任务范围与产物粒度相互独立：

```text
创建任务：一幕或一个连续批次
最终产物：一章一个 prompts/vol-N-ch-M.md
```

## 创作上下文

prompt-crafter 的知识输入默认来自本卷 `settings/context-pack.md`（预制包）：它由本卷首个 `prompt.create` 任务按 `skills/context-pack.md` 从知识库裁剪压缩而成，覆盖题材、连载基线、剧情/场景/人物方法。后续任务读这一包即可，不再逐章下钻 `knowledge/`。本卷首个 `prompt.create` 任务尚未形成 pack 时，先按 `skills/context-pack.md` 建包，再继续创建章级 Prompt。

幕级理解优先来自 `chapters/vol-N-act-K-handoff.md`（幕级承接快照，由 chapter-planner 在完成本幕章纲后生成）：它汇总承接入口、本幕变更事实链、must_hold 与幕间接口，替代逐文件重建幕级理解。快照缺失或与幕纲/章纲不一致时，才从当前幕纲、任务范围内的章纲、批次入口和出口、必要人物设定、已确认项目文风、题材、作者确认偏好、伏笔、时间线、有效正文入口和少量相关知识建立幕内理解。它只读取与当前章有关的项目事实，不把原始设定整段搬进 Prompt。

Prompt 的自包含性标准见 `knowledge/scene/self-contained-prompt.md`（三自原则、各节嵌入规则、幕级上下文转化方法、自检协议）。prompt-crafter 在创建每份 Prompt 后必须执行自检协议中的七项检查；Prompt 中不允许出现章/幕/卷编号引用、外部文件引用或未嵌入的叙事意图。

`settings/writing-style.md` 提供本项目的声线锚点（基准样章、对照示范、节奏配比和声线禁区），`settings/genre-setting.md` 提供题材期待。创建者从文风文件中提取两层材料：一是全章基调，用它亲自书写"本章故事"的叙述，让故事叙述本身成为 writer 拿到的第一声线示范；二是逐场声线落点，为每场选取句长倾向、对白与叙述配比、感官密度、留白位置和一句样句锚点，写入该场的"本场声线"。writer 不必再回到这些来源寻找上下文。

Prompt 用连贯叙述锁定会影响后续承接的事实、人物选择、场景压力和代价，不替 writer 写完对白或安排每个动作。"本章故事"和各场叙述写清发生什么、为什么发生、谁付出什么代价；对白措辞、动作编排、段落切分仍是 writer 的现场创作。把知识改写成当前人物能感知、能误判、能采取的行动；不要把“紧张、感人、爽、真实”当作可执行指令。

如果文风文件仍是占位符、只有抽象形容词，或没有作者确认的样章，先把缺口和需要作者选择的方向返回顶层，不要自行补成通用模型腔。Prompt 可以暂缓，不能用空泛的声线形容词掩盖声线尚未形成。

文风原型库只参与项目文风形成，不参与每章 Prompt 的默认读取。项目文风确认后，prompt-crafter 只提取当前章节需要的声线特征、各场样句方向和少量边界；不要把原型名称、来源印记或整套原型规则写进 Prompt。

## 建包返回摘要

本卷首个 `prompt.create` 任务在建包后、创建章级 Prompt 前，向顶层返回一份建包摘要，供顶层低成本抽查包质量：

- 题材执行要点一句话（本卷题材期待如何被压缩进包）。
- 已确认边界清单（题材边界、作者边界、声线禁区是否入包）。
- 来源清单（实际读取的索引与子文件，与 `settings/context-pack.md` 头部 `sources` 一致）。
- 一致性声明（包内容与 `settings/genre-setting.md`、`settings/writing-style.md` 已确认内容是否对齐，冲突时注明）。

顶层据摘要抽读 pack 一节核对；发现压缩失真或遗漏时按 `skills/context-pack.md` 的补包/重建规则处理。

## 单章 Prompt

每份 Prompt 独立写入 `prompts/vol-N-ch-M.md`，由四节组成：本章故事、人物动机与情绪、场景展开、必守事实与边界。前三节以连贯叙述为主体，声线与技法逐场溶解，不设独立的声线分节。

```markdown
---
prompt_contract: 3
chapter: vol-1-ch-1
act: vol-1-act-1
target_chars: 4000
min_chars: 3200
---

## 本章故事
{300–500 字连贯叙述。从上一章收束的具体画面起笔：人物此刻在什么时间、什么地点、手上有什么、刚发生过什么、眼下被什么逼着；然后讲清本章要走的完整一段路：遇到什么阻力、经过几次交锋、在哪里转向、付出什么代价；最后落到收束的新状态。这段叙述本身用项目声线来写，它就是 writer 拿到的第一声线示范，胜过任何形容词。}

收束：{正文停在哪个具体画面：人物在做什么、留下了什么可见证据，1 句}
读者期待：{本章回应、加深或转移的具体问题，1–2 句}

## 人物动机与情绪
{每个出场人物一小段连贯叙述（3–5 句）：他进场时想要什么、怕什么、误判了什么（起点）；本章哪个事实或压力会撬动他（施压点）；他的目标或情绪在哪一刻转向、转向后剩下什么（落点）。写递进弧线，不写此刻快照；不写性格标签。}

情绪线：{全章情绪从什么基调起、在哪一场升或压、收在什么温度；对应该章节奏型：哪里密集推进、哪里放缓换气，1–2 句}

## 场景展开

### 场景：{名称}｜权重：核心/承接/转折
{3–6 句连贯叙述讲这场戏怎么过：谁带着什么进场、想要什么、被什么挡住、双方怎样试探施压、什么改变了判断、人物付出什么代价、留下什么新局面。}
- 行动脉络：入场状态 → 目标与阻力 → 行动与反制 → 转折与选择 → 可见结果 → 下一步触发（各环节一句完整话，锁定因果，不编排对白措辞）
- 本场怎么写：{针对这场戏的性质（对峙/试探/日常/追逐/独处……）给出的 2–4 条具体展开指导，从 context-pack 技法转化为本场的动作、对白、感官设计；落到这一场的人、事、物上，不点名方法名，不写放之四海皆准的抽象指令，多场之间不得复诵同句}
- 本场声线：{这一场的句长倾向、对白与叙述配比、感官密度、何处留白（哪些话直说、哪些只给动作和停顿），加一句样句锚点（从 writing-style.md 基准样章选取或按其声线原创）}

## 必守事实与边界
- 必须发生：{通过人物行动交付的变化}
- 相关事实：{本章真正需要的身份、能力、资源、信息阶段}
- 保留边界：{会影响后续承接、本章不能动的事实清单}
```

Prompt 通过人物行动组织内容。事件名称、结果清单、方法标签和抽象主题不能代替人物目标、阻力、反制、选择与后果。写作者不必按小节顺序写正文，也不必逐节显式交付；叙述与骨架只是保证关键因果不丢，正文仍应像人物在当下做事、说话、犹豫和承担后果。

`target_chars` 和 `min_chars` 只是分配场景展开空间的粗略参考，不是交付下限、质量评分或注水理由。篇幅应服从人物选择、读者理解和场景余波；关键处需要更多空间时可以超出，过渡处成立时也可以更短。

## 四步转化法（章纲 → 单章 Prompt 的过程）

写每份 Prompt 前，按四步把章纲的可执行内容转化为人物可以经历的行动过程。四步是**写的过程**，与下方的自检（**写完的检查**）衔接，不是两套检查清单：

1. **锚定角色**：从章纲 `conflict` 与 `characters` 出发，确立每个人物本章的动机起点：表层想要什么、不愿承认什么、已知/未知/误判什么、筹码和底线在哪；只写本场会实际作用的条目，不写性格标签。
2. **锚定信息差**：从章纲 `characters` 的信息差轨迹（若有）与幕纲 `start_state`/`end_state` 出发，明确本场谁知道什么、谁不知道什么、谁在误判；信息差决定哪个事实或压力会在本章撬动人物，成为动机与情绪的施压点。信息差轨迹缺失或过简时，从幕纲 `start_state`/`end_state` 与 `scenes` 的对抗结构反推本场信息状态，不因字段可选而跳过这一步。
3. **锚定情绪递进**：从幕纲 `emotional_curve` 与章纲出发，确定每个人物在本章的转向与落点（目标或情绪在哪一刻变、变成什么），以及全章情绪线（从什么基调起、在哪一场升或压、收在什么温度）；情绪来自事件后果与人物反应，不来自抽象标签。
4. **溶解输出**：先把承接、压力、交锋与代价写成连贯的「本章故事」叙述，叙述语言本身调用项目声线；再逐场写出场景叙述与行动脉络，按该场性质把场景技法溶解为「本场怎么写」的具体指导，把声线落为「本场声线」；关键选择留下余波。场景性质（对峙/试探/日常/追逐/独处等）以章纲 `scenes` 主导任务为判断依据，拿不准时按 `skills/planning.md` 的场景知识指引回读 `knowledge/scene/index.md` 对应条目，不凭感觉贴标签。

场景权重标注：每章标注 **1 个核心场景**（展开最充分，承担本章主要变化）与**至多 1 个低权重转场**（过渡性，控制篇幅）。低权重转场建议不超过 100 字：1 句环境 + 1 句动作 + 1 句氛围即可，不为凑字数展开；其「本场怎么写」与「本场声线」可从简合并为一两句。

## 案例骨架（四节结构示范）

下面是单章 Prompt 的四节结构骨架，示范每节应有的信息粒度与职责（示意结构，非固定文案）：

```markdown
---
prompt_contract: 3
chapter: vol-N-ch-M
act: vol-N-act-K
target_chars: 4000
min_chars: 3200
---

## 本章故事
一段连贯叙述（300-500 字）：承接上一章状态，写入本章事件与人物动作，落在一个可见结果上；叙述语言本身即项目声线示范。后附一行收束画面、一行读者期待回应。

## 人物动机与情绪
每人一段：起点（表层想要什么、不愿承认什么、已知/未知/误判）→ 施压点（哪个事实或压力在章内撬动他）→ 落点（目标或情绪在哪一刻变、变成什么）。后附一行全章情绪线（从什么基调起、在哪一场升或压、收在什么温度）。

## 场景展开
每场四件齐，并标注权重（核心/转折/低权重转场）：
- 场景叙述：2-4 句，写事件与动作。
- 行动脉络：入场→目标阻力→行动反制→转折选择→可见结果→下一步触发。
- 本场怎么写：把技法溶解为具体指导，不复诵方法名。
- 本场声线：落到节奏、对白密度与留白处，附一句样句。

## 必守事实与边界
- 必须发生：本章不可绕开的事实。
- 相关事实：需要照应但不正面展开的背景。
- 保留边界：本章不揭破、不登场、不展开的内容。
```

## 自检结论

prompt-crafter 返回顶层时，必须按章附一行式自检表：覆盖 `knowledge/scene/self-contained-prompt.md` 自检协议七个检查项（按返回粒度合并为五核对点）+ 字段完整性核对点。每项只填「成立」或「缺口 + 证据」，不评分、不写分析：

```text
章节 | must_hold 全部落入 | 故事连贯含承接收束 | 动机情绪有递进 | 场景有行动-反制-选择-余波 | 每场声线有落点且不复诵 | 字段完整性
vol-N-ch-M | 成立 | 成立 | 成立 | 成立 | 成立 | 成立
vol-N-ch-Q | 缺口: 章纲 must_hold 的 X 事实未写入必守事实 | ... | ... | ... | ... | 缺口: 本章故事缺收束画面
```

字段完整性核对点：本章故事含叙述 + 收束 + 读者期待；人物动机与情绪每人含起点/施压点/落点且含情绪线；场景展开每场含场景叙述/行动脉络/本场怎么写/本场声线（缺低权重转场可注明从简）；必守事实与边界三件齐。

自检表是顶层逐一读 Prompt 时的核对锚点：顶层对范围内每份 Prompt 逐一读过（存在 ≠ 通过），逐行核对自检表，对标记"成立"的章节抽读原文 2-3 章复核。自检结论的成立与否由顶层阅读验证，不构成脚本门禁；发现缺口时由 prompt-crafter 修复对应 Prompt，或按缺口性质返回规划层。

## 幕内连续性

prompt-crafter 按章节顺序创建文件。每章的收束与下一章入口共同来自幕纲和章纲；批次结束时确认出口能够交给下一批次继续创建。

批次任务返回时附**批次出口摘要**：承接入口、本批已锁事实、末章 `ends_with`、下一批次需要注意的连续性要点。出口摘要由顶层在任务间传递，下一批次 prompt-crafter 直接读取，不再重读全部章纲推导出口。

创建者遇到幕纲和章纲无法共同成立的情况时，把冲突和受影响范围返回顶层。Prompt 不替规划层改写上位事实。

## 完成语义

当前幕或 batch 完成后，顶层继续长期目标范围内的下一段 Prompt 创建。长期 `range` 内每章的 Prompt 全部创建并落盘后，cursor 才进入 `prompts.ready`；这个节点表示所选写作范围已经可以整体进入写作模式或编辑模式。

## 显式 Prompt 审查

只有用户明确提出审核提示词时，顶层创建 prompt-reviewer，并建立临时 `prompt.review` 任务。

reviewer 先单独阅读目标 Prompt，判断它自身能否形成清楚、可执行的人物行动；随后只增加所在幕纲和对应章纲，核对 Prompt 与规划的关系。审查结果写入当前 task，不改变默认 Prompt 创建链。
