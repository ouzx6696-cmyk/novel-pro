# 冷读纪律（共享模块）

本模块是 reader 和 completion-reviewer 共用的冷读协议与分流语义权威源。`skills/review-archive.md` 和 `skills/completion-quality.md` 引用此处，不另建平行表述。

## 冷读协议

1. 先只读正文。首读阶段不读取幕纲、章纲、Prompt、设定、知识库、既有报告或问题清单。
2. 首读记录真实阅读反应：理解、误解、期待、疑问、情绪投入和幕末感受。
3. 没有读者实际感受到的问题，不从规则清单中虚构。
4. 首读完成后，才读取诊断所需的上下文（continuity contract、目标 Prompt、创作知识），追查正文中真实出现的问题。
5. 不得用关键词搜索、问题计数、字段覆盖或脚本扫描替代阅读。

## 首读要留下什么

首读不是寻找违规项，也不是给章节打分。先留下读者真正经历过的东西：

- 哪个瞬间让人看懂人物正在争取什么，哪个瞬间让人失去方向。
- 哪个动作、细节或关系反应让场景像真实发生，哪里像作者在替人物说明。
- 人物是否有自己的面子、恐惧、误判和不愿说出口的东西；选择是否改变了他下一步能做什么。
- 对话中的权力、距离和潜台词是否在变化，表达是否仍然保住项目声线。
- 章末或幕末留下的是具体期待，还是只有总结、预告或抽象情绪。

报告先记成立处和读者投入，再记真正妨碍阅读的问题。没有正文证据的问题不进入返修。

## HARD FIX: synopsis delivery

章纲或 Prompt 承诺的关键场景在正文中只剩结果播报、旁白概述、会后复盘或几段结论性对白时，标记 `HARD FIX: synopsis delivery`。

具体表现（非穷尽）：关键场景只有结论、人物没有在场行动、阻力未实际作用、选择与后果被一句带过。即使事实终点正确、篇幅看起来充足也不能 PASS。人物必须实际采取策略、遭遇阻力、调整判断或付出选择，并产生可见后果。

始终以正文证据为准：关键场景是否被写成可经历的行动过程。

## 分流语义

- `IGNORE`：正文成立，保留原文，不创建返修。
- `EDIT`：边界清楚的局部表达、局部可信度、局部连续性或清晰度问题。连续性涉及跨章事实或核心因果时，升级为 `REGENERATE`。
- `REGENERATE`：核心因果、人物动机、信息时序、场景骨架、跨章承接或 Prompt 设计失败。

三者互斥。表达问题与内容问题不能合并成一个返修任务。边界不清时保留原候选，交 Reader 判断。

返修以最小改变为原则：能通过删掉解释、恢复动作或调整一处顺序解决，就不重写整场；只有核心选择、因果或人物声音已经失真时，才扩大范围。读者没有指出的有效粗粝、留白和个性不因“更整齐”而被抹平。

## 复读纪律

每次返修后重新顺序冷读指定范围，重新判断人物信息、场景因果、阅读节奏、期待变化和幕终点。不能只核对原问题卡是否逐条消失。返修中新出现的问题与原问题同等处理。未复读接受的候选不得提交。

### 复读范围判定清单

复读范围按返修类型确定（判定是阅读指引；涉及跨章事实或核心因果的局部问题必须升级为 `REGENERATE`，不能按局部 `EDIT` 处理）：

- 单章局部 `EDIT`（局部表达/可信度/清晰度）：自受影响章的前一章末段顺序复读至该章。
- 单章 `REGENERATE`（整章重写）：自前一章顺序复读至该章，核对承接入口与重写后的章末状态。
- 跨章或跨幕变化（多处返修、事实链/承接/因果受牵连）：复读当前整幕。
- Prompt 或幕纲/章纲修复：先由对应角色完成产物修复、顶层阅读确认，再重新写作并复读；不复读未经确认的修复产物。
- 完本 `completion.revise`：候选经受影响范围复读后，再做一次全书承接复读。
