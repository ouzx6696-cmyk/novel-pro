## 5分钟了解novel-pro

### novel-pro是什么？

一个**独立运行的文学内核**，帮助你创作中文长篇小说。它：
- ✅ 从题材初始化到完本质检的**全流程支持**
- ✅ 用卷/幕/章三层规划保持**长线连续性**
- ✅ 用单章自包含Prompt保持**创作注意力**
- ✅ 用Reader冷读+Anti-AI扫描实现**文学验收**

### 你需要什么？

- **必需**：Agent Host（如Claude Desktop + ZCode）
- **可选**：Novel Desk（本地工作台）
- **技能**：基本的Markdown编辑能力

### 工作原理

```
你提供：题材方向 + 故事构思
          ↓
novel-pro帮你：
  1. 规划卷纲/幕纲/章纲
  2. 创建单章自包含Prompt
  3. 派发独立writer写作
  4. Reader冷读 + Anti-AI扫描
  5. 整体返修 + 正文提交
          ↓
你获得：可发布的正文章节
```

## 15分钟快速开始

### 第1步：初始化项目（2分钟）

**前置条件**：确保已安装novel-pro skill

**操作**：
```bash
# 在你的项目目录
python tools/init.py
```

**按提示操作**：
- 交互只要求选择题材编号（1-25），项目名取当前目录名
- 也可命令行指定：`python tools/init.py <项目路径> --genre <题材编号>`，或用 `--genre-name <题材名>` 按名称指定

**生成结果**：
- 项目骨架（volumes/、acts/、chapters/等目录）
- `story.md`（主故事文件）
- `CLAUDE.md`（项目配置）
- `.agent/`（控制面目录）

---

### 第2步：填写故事主线（3分钟）

打开 `story.md`，填写四个核心问题：

```markdown
## 故事主线
- 主角想要什么：重返修仙界夺回传承
- 核心阻力：现代都市无灵气+仇家追杀
- 失败代价：永远困在地球，仇家毁掉师门
- 最终变化：重建灵脉，带领地球修仙复兴
```

**填写技巧**：
- 用具体动词（夺回、证明、找到）
- 避免抽象词（变强、成功、幸福）
- 确保可检验成败

---

### 第3步：与Agent对话开始规划（5分钟）

**在Agent对话中**：

```
我：开始规划第一卷

Agent会：
1. 读取story.md的故事主线
2. 调用volume-planner
3. 与你共同完善卷纲：
   - 本卷目标（如"在都市站稳脚跟"）
   - 冲突阶梯（4-5级递进）
   - 人物设定（主角、关键配角）
   - 项目文风（选择原型+提供样章）
```

**你需要确认**：
- 卷纲是否符合预期
- 人物设定是否清晰
- 文风样章是否满意

**确认后**：
- Agent将 `story.md` 对应卷的 `author_confirmed` 改为 `true`
- 解锁下一阶段

---

### 第4步：规划幕和章（3分钟）

```
我：继续规划幕纲

Agent会：
1. 创建幕地图（整卷分几幕）
2. 创建详细幕纲（每幕的压力点）
3. 创建章纲（每章的目标和场景）
```

**你只需**：
- 查看规划是否合理
- 确认推进

**自动生成**：
- `acts/volume-1-acts.md`（幕地图）
- `acts/vol-1-act-1.md`（详细幕纲）
- `chapters/vol-1-ch-1.md`（章纲）
- `chapters/vol-1-act-1-handoff.md`（承接快照）

---

### 第5步：顺序链路创建Prompt并写作（2分钟）

```
我：开始写第1章（写作模式）

Agent会（顺序链路，逐章推进）：
1. 调用prompt-crafter创建第1章Prompt
2. 本卷首任务从知识库压缩打包context-pack
3. 从上一章真实正文提取前情三件套 + 状态文件倒读角色初始状态
4. 调用prompt-reviewer默认审计（9维度）
5. 调用writer写第1章草稿
6. 顶层阅读判定，验收后 state.update 回流状态
7. 再创建第2章Prompt（前情直接取自第1章真实草稿）
```

**Prompt包含六块**：
- 前情上下文（上章结尾画面/情绪残留/缺口，取自真实正文）
- 本章故事（叙述示范）
- 角色初始状态（位置/状态/已知信息/持有物）
- 人物动机与情绪（起点→施压→落点）
- 场景展开（每场的行动脉络+声线落点）
- 必守事实与边界（含信息差变化）

**选择模式**：

**写作模式（快速草稿）**：
```
我：用写作模式快速写第1章
```
- 产出到 `drafts/vol-1-ch-1.md`
- 不经Reader验收
- 适合快速推进看全貌

**编辑模式（文学验收）**：
```
我：用编辑模式写第1章
```
- 经过Reader冷读 + Anti-AI扫描
- 整体返修裁决
- 产出到 `texts/vol-1-ch-1.md`
- 适合精修到可发布

## 核心概念

### 1. 四层架构

```
工具层（tools/）
  - init.py: 初始化项目
  - migrate.py: 项目迁移
  - sync_runtime.py: 运行时同步
    ↓
模板层（templates/）
  - 定义项目结构
  - 提供骨架和字段
    ↓
技能层（skills/ + agents/）
  - 14个skill模块
  - 12个agent角色
    ↓
知识层（knowledge/）
  - 通用写作底座（跨题材）
  - 类型风格知识（题材专属）
```

### 2. 卷/幕/章三层结构

```
卷（Volume）
  - 一个大的叙事阶段
  - 有独立的目标/冲突/结束
  - 推进全书主线
  - 示例：20-80章
    ↓
幕（Act）
  - 卷内的子阶段
  - 有明确的戏剧任务
  - 示例：8-15章
    ↓
章（Chapter）
  - 最小叙事单元
  - 有独立的场景和变化
  - 示例：3000-5000字
```

**为什么三层？**
- **卷**：管理长线驱动力和冲突升级
- **幕**：管理阶段性压力和承接
- **章**：管理单次阅读体验

### 3. 两种创作模式

| 特性 | 写作模式 | 编辑模式 |
|---|---|---|
| 目标 | 快速草稿 | 文学验收 |
| 流程 | writer → drafts/ | writer → Reader → Anti-AI → 返修 → texts/ |
| 验收 | 顶层阅读判断 | 完整六步闭环 |
| 时间 | 快（3-5分钟/章） | 慢（20-30分钟/幕） |
| 适合 | 先看全貌、快速推进 | 精修到可发布水平 |

**如何选择？**
- 初稿阶段：写作模式
- 修改润色：编辑模式
- 可以混用：先用写作模式快速写完，再用编辑模式精修

### 4. 自包含Prompt

**核心创新**：每章的Prompt是自包含的生成包，writer不需要查找外部上下文。

**三自原则**：
- **自说明**：Prompt自身说清所有关键事实
- **自闭合**：起点和终点状态都在Prompt内
- **自锚定**：文风指导不依赖标签，而是叙述示范+逐场落点

**好处**：
- ✅ 每章独立上下文，避免污染
- ✅ 批量创建仍保持质量
- ✅ 可以并发执行

### 5. 冷读纪律

**什么是冷读？**  
Reader首次阅读正文时，不预先加载规划/Prompt/知识，先产生真实阅读反应。

**为什么重要？**  
- 避免用规则清单虚构问题
- 保持对真实正文的判断
- 发现问题后才追查根因

**执行纪律**：
1. 先读正文 → 记录理解/期待/疑问
2. 再读规划 → 对比规划与正文差异
3. 追查根因 → 判断是正文执行问题还是Prompt设计问题

## 典型工作流

### 工作流1：新书启动（第一卷）

```
Day 1-2：构思与规划
  1. 填写story.md故事主线
  2. 规划第一卷卷纲（与Agent对话）
  3. 确认人物设定和项目文风
  4. 规划幕地图和详细幕纲
  5. 规划第一幕章纲
  
Day 3：创建Prompt
  6. 创建第一幕的所有Prompt
  7. 检查context-pack是否生成
  
Day 4-7：写作模式快速推进
  8. 用写作模式写完第一幕（8-10章）
  9. 顶层阅读草稿，确认方向
  
Day 8-10：编辑模式精修
  10. 用编辑模式重新处理第一幕
  11. Reader冷读 → Anti-AI扫描 → 返修
  12. 提交到texts/，第一幕完成！
```

### 工作流2：单卷创作（后续卷）

```
前置：第N-1卷已完成

Step 1：规划新卷
  1. 填写story.md第N卷的表格行
  2. 规划新卷卷纲（承接上卷状态）
  3. 确认后标记author_confirmed = true
  
Step 2：幕章规划
  4. 规划幕地图（整卷节奏）
  5. 逐幕规划详细幕纲
  6. 逐幕规划章纲
  
Step 3：Prompt创建
  7. 逐幕创建Prompt（复用context-pack）
  
Step 4：选择模式创作
  8a. 写作模式：快速完成全卷草稿
  8b. 编辑模式：逐幕精修并提交
  
Step 5：卷末对齐
  9. 整卷对齐（确保规划与正文一致）
  10. 标记volume.complete
```

### 工作流3：返修与完本

```
场景1：中途发现问题
  - 如果是单章表达问题 → Anti-AI局部编辑
  - 如果是Prompt不足 → prompt-crafter修Prompt
  - 如果是规划冲突 → 对应planner调整
  
场景2：显式完本质检
  1. 运行completion.inspect（全书冷读）
  2. 获得完本报告（IGNORE/EDIT/REGENERATE分流）
  3. 按报告返修
  4. 复读验证
  
场景3：整卷对齐
  - 当规划和正文不一致时
  - 运行alignment操作
  - 不动已接受正文，只调整未执行规划
```

## 常见问题FAQ

### Q1: 我需要编程经验吗？

**A**: 不需要。你只需要：
- 会编辑Markdown文件
- 会与Agent对话
- 理解基本的小说创作概念

初始化和迁移用Python脚本，但都是简单的命令行操作。

---

### Q2: 支持哪些题材？

**A**: 当前支持25个题材，包括：
- 修仙：xianxia（修仙）、xuanhuan（玄幻）
- 现代：urban（都市）、romance（言情）
- 推理：suspense-crime（悬疑推理）
- 历史：historical（历史）
- 其他：scifi（科幻）、fantasy（西幻）等

完整列表见 `knowledge/genre/index.md`

---

### Q3: 一章写多久？

**A**: 取决于模式和复杂度：
- 写作模式：3-5分钟/章
- 编辑模式：20-30分钟/幕（8-10章）
- 包含规划、Prompt、写作、返修全流程

---

### Q4: 生成的内容质量如何？

**A**: novel-pro的设计目标是**可发布水平**：
- ✅ 人物行动有因果逻辑
- ✅ 场景展开真实可信
- ✅ 声线统一不飘
- ✅ 无AI味模板化表达（经Anti-AI扫描）
- ✅ 长线连续性（卷/幕/章规划保障）

但仍需要：
- 作者参与规划确认
- 必要时手动调整
- 最终发布前人工审核

---

### Q5: 可以中途暂停吗？

**A**: 完全可以。恢复机制保证：
- 保留已有产物（规划/Prompt/草稿）
- 从最小恢复入口继续
- 不重建已成立的范围

直接继续对话即可，novel-agent会自动读取现场状态。

---

### Q6: 如何修改已生成的内容？

**A**: 三种情况：

**情况1：草稿阶段**（drafts/）
- 可以直接编辑文件
- 或让Agent用同一Prompt重派writer

**情况2：已提交正文**（texts/）
- 用编辑模式的edit.repair返修
- 或用completion.revise显式修改

**情况3：规划阶段**（还没写正文）
- 直接修改规划文件
- 重新创建Prompt

---

### Q7: Novel Desk是什么？必须用吗？

**A**: Novel Desk是**可选的**本地工作台：
- 提供文件编辑界面
- 展示报告和快照
- 提供任务入口（通过TASKS.md）

**不用Desk也可以**：
- 用任何编辑器编辑Markdown文件
- 通过对话式操作Agent
- 原有工作方式不受影响

---

### Q8: 旧项目如何升级？

**A**: 必须运行完整迁移：

```bash
python tools/migrate.py <旧项目路径> <新项目路径>
```

**迁移做什么**：
1. 在新目录初始化当前版本项目
2. 搬运故事、设定、规划、正文
3. 生成迁移报告

**作者操作**：
1. 核对 `.migration/report.md`
2. 运行 `finalize <新项目>`
3. 按报告运行 `cleanup <新项目> --confirm`

**注意**：清理只删除旧运行时文件，不删除正文和规划。

---

### Q9: 如何查看当前进度？

**A**: 查看 `.agent/status.yaml` 的 `cursor.step` 字段：

| cursor.step | 含义 |
|---|---|
| outline.volume | 正在规划卷纲 |
| outline.acts | 正在规划幕纲 |
| outline.chapters | 正在规划章纲 |
| draft.write | 顺序链路：逐章 Prompt 创建/审计/写作/编辑/状态同步 |
| drafts.ready | 草稿已完成（写作模式终点） |
| volume.complete | 当前卷已完成 |
| book.complete | 全书已完成 |
| migration.review | 迁移报告等待复核（迁移期间） |

顺序链路下没有"Prompt 批量就绪"节点：Prompt 跟随正文顺序逐章创建，第 N+1 章 Prompt 的前情直接取自第 N 章真实验收稿。
