# 返修方法论

## 什么时候有用
编辑模式中 Reader 冷读后发现问题、edit-synthesizer 裁决返修方案、writer 或 anti-ai 执行返修时。指导如何判断返修类型、形成返修焦点、执行返修和验证返修效果。

## 想产生什么效果
返修精准解决问题，不破坏已经成立的文字；返修范围最小化但彻底解决问题根因；返修后正文比返修前更好，不引入新问题。

## 核心原则

### 返修基于证据，不基于清单
返修只处理正文已经证明的问题。不为满足规则清单而制造新句子，不为凑指标而修改已经成立的文字。

### 保留生命力
优先保留已经有生命力的语气、动作和关系细节。返修是修问题，不是重写。

### 根因导向
表面问题修表面，根因问题修根因。Reader 报告的根因归属决定了返修路径。

## 返修类型判断

### 内容问题（REGENERATE）
**特征**：人物行动缺乏因果、场景骨架不成立、信息时序错误、跨章承接断裂。
**根因**：正文执行不足 / Prompt 设计不足 / 规划层冲突。
**返修路径**：
- 正文执行不足 -> 新 writer（原 Prompt）重写
- Prompt 不足 -> prompt-crafter 修 Prompt -> 新 writer 重写
- 规划冲突 -> 对应 planner 调整 -> 修 Prompt -> 重写

### 表达问题（局部编辑）
**特征**：AI味、模板化表达、解释腔、机械重复、不自然对白。
**根因**：执行层面的表达习惯，不涉及内容结构。
**返修路径**：anti-ai 编辑模式，在 edit-boundary 内局部修改。
**边界**：完整禁止清单见 `skills/edit-boundary.md`（唯一权威源）；越界即返回上游，不自行放宽。

## 返修焦点形成

### 从 Reader 报告提取
- 问题定位：哪一章、哪一场、哪一段
- 问题性质：内容还是表达
- 根因归属：正文执行 / Prompt 设计 / 规划层
- 严重等级：严重 / 中等 / 轻微
- 最小处理范围：只修问题段落还是整场重写

### 从 Anti-AI 报告提取
- 原句定位：精确到段落
- AI味表现类型：解释腔 / 模板化 / 机械重复 / 不自然对白
- 严重倾向：严重 / 中等 / 轻微
- 是否越界：局部可编辑 / 需 REGENERATE

### 返修焦点写法
好的返修焦点：
- 具体到段落和问题："第3场第5段，师妹追上来后只说了两句话，她的复杂情绪没有展开"
- 指明方向但不指定措辞："需要展开师妹的犹豫和担心，但不能让她直接说出来"
- 标注保留项："前两场的声线节奏保留，只修第3场"

坏的返修焦点：
- 太抽象："这里写得不好，改好一点"
- 指定措辞："把这句话改成XXX"
- 范围不清："这一章都要改"

## 返修执行

### 内容返修（writer 重写）
1. 保留原 Prompt 中成立的部分
2. 只修改问题对应的 Prompt 节（如场景展开的具体行动脉络）
3. 新 writer 从修改后的 Prompt 重新创作**完整章节**（不是只改问题段落）
4. 新草稿与原草稿都保留，供 Reader 复读比较

### 表达返修（anti-ai 局部编辑）
1. 只修改 Anti-AI 报告点名的段落
2. 在 edit-boundary 内操作
3. 保留原文的叙事骨架和人物选择
4. 只改表达方式，不改内容
5. 修改后的段落要自然融入上下文，不能有缝合痕迹

## 返修验证

### 复读验证
- 返修后必须重新顺序冷读受影响范围
- 不能只检查原报告中的问题是否消失
- 要重新判断人物信息、场景因果、阅读节奏、期待变化

### 最小返修范围判定
- 单章局部 EDIT：自受影响章前一章复读
- 单章 REGENERATE：自前一章至该章复读
- 跨章/跨幕：整幕复读
- Prompt 或幕纲变化：先修产物、顶层确认、再写作复读

### 返修成功标准
- 原问题已解决（Reader 确认）
- 没有引入新问题（复读无新问题）
- 已经成立的文字没有被破坏
- 声线一致性保持

## 常见失败模式

### 过度返修
- 返修范围超出问题范围，破坏了已经成立的文字
- 纠正：严格遵循最小返修范围

### 表面返修
- 只修了表面问题，根因没有解决，问题会在后续章节重现
- 纠正：追查根因，按根因归属选择返修路径

### 返修引入新问题
- 返修后的段落与上下文不连贯，引入了新的表达问题
- 纠正：返修后必须复读，不能只看修改段落

### 指定措辞
- 返修焦点变成了具体措辞指令，writer 只是执行替换
- 纠正：返修焦点指向问题和方向，不指定具体写法
